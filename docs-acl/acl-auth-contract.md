# ACL 官网授权页 · 接口契约

面向：负责官网授权页的 Agent
版本：v1
日期：2026-10-27

## 背景

ACL 启动器需要把「公会账号登录」迁移到官网，点击侧边栏登录按钮后跳转官网授权，授权完成后回到启动器。启动器不保存密码，只保存官网签发的会话令牌。

采用 RFC 8252 规定的**本机回环回调**，不使用自定义 URL 协议（避免 Windows 上协议被抢注导致令牌截获）。

## 启动器发起的请求

```
GET https://yingzhou1110.top/acl/auth?port=<端口>&state=<随机串>&v=1
```

| 参数 | 说明 |
| --- | --- |
| `port` | 启动器临时监听的端口，范围 1–65535 |
| `state` | 32 位十六进制随机串，用于防重放与防注入，**必须原样回传** |
| `v` | 协议版本，当前固定 `1` |

## 页面职责

1. 校验 `port` 是合法整数（1–65535）且 `state` 非空；不合法则显示错误页，不跳转
2. 未登录：展示登录表单（沿用官网现有账号体系），可提供注册入口
3. 已登录：展示确认页，文案示例「ACL 请求访问你的公会账号」，提供「允许」与「取消」
4. 用户点「允许」后跳转：

```
http://127.0.0.1:<port>/callback?state=<原样回传>&token=<会话令牌>&user_id=<用户 ID>&name=<显示名>
```

5. 用户点「取消」：跳转到同一地址但不带 `token`，参数仅 `state` 与 `error=cancelled`

**安全要求（必须实现）**：

- 跳转目标**只能**是 `http://127.0.0.1:<port>/callback`，禁止接受其他 host 或路径，防止开放重定向
- 不得把 `state` 换成新值，必须原样回传
- 令牌仅通过回环地址传递，不走前端 localStorage 之外的持久化

## 令牌约定

| 项 | 说明 |
| --- | --- |
| 会话令牌 | 官网当前登录态对应的令牌，放在 `token` 参数 |
| 后续调用 | 启动器以请求头携带该令牌调用公会数据接口（头名由后端确定，见下） |
| 有效期 | 与官网会话一致；过期返回 `401`，启动器清除本地登录态并提示重新登录 |

**请求头名称：`x-studio-token`**（沿用官网功能页账号的会话令牌，每个成员账号独立，普通成员 `role='user'`，管理员另计）。

## 令牌约定（已确定）

| 项 | 说明 |
| --- | --- |
| 令牌来源 | 官网功能页账号登录后签发的会话令牌（`x-studio-token` 对应的值） |
| 请求头 | 启动器调用公会接口时带 `x-studio-token: <token>` |
| 有效期 | 与官网一致（7 天）；过期返回 `401`，启动器清除本地登录态并提示重新登录 |
| 权限 | 普通成员 `role='user'`，只能读公会数据；管理员权限与本功能无关 |

## 启动器侧行为（已实现）

- 监听 `127.0.0.1:随机端口`，5 分钟无回调则超时
- 校验 `state` 一致，否则拒绝并提示重试
- 用户点「取消」时页面跳回带 `error=cancelled`，启动器提示「已取消」
- 成功后写入本地会话文件，并向用户展示「登录成功，可关闭此页面」
- 令牌不进入界面层，前端只拿到用户 ID 与显示名
